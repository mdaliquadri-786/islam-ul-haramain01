## 5. Read-Only Forensic Root-Cause Analysis

### Forward-Reference Dependency Bug:
1. **Usage in Migrations 12, 13, 14:**
   - Migration 12 (`20260924000003_audio_streaming_reciters.sql`), Migration 13 (`20260924000004_tafsir_comparative_viewer.sql`), and Migration 14 (`20260924000005_digital_islamic_books_ereader.sql`) all enforce admin RLS policies using:
     `public.is_platform_admin(auth.uid())`
2. **Where `is_platform_admin` is Defined:**
   - In Migration 17 (`20261001000000_m9_rls_hardening.sql`), line 5 and line 19 explicitly document and define:
     ```sql
     -- 1. Create missing public.is_platform_admin function
     -- Referenced in:
     --   - 20260924000003_audio_streaming_reciters.sql (audio_reciters, audio_surah_files)
     --   - 20260924000004_tafsir_comparative_viewer.sql (tafsir_works, tafsir_editions, tafsir_entries)
     --   - 20260924000005_digital_islamic_books_ereader.sql (books, book_editions, book_volumes, book_sections, book_contents)
     CREATE OR REPLACE FUNCTION public.is_platform_admin(lookup_uid UUID DEFAULT auth.uid())
     RETURNS BOOLEAN AS $$
     BEGIN
         IF lookup_uid IS NULL THEN
             RETURN FALSE;
         END IF;

         -- Delegates to canonical is_admin check defined in 20260925000001
         RETURN public.is_admin(lookup_uid);
     END;
     $$ LANGUAGE plpgsql SECURITY DEFINER SET search_path = public, pg_temp;
     ```
3. **The Chronological Sequencing Flaw:**
   - Migration 17 was written as an additive patch during Milestone M9.
   - The authors added `public.is_platform_admin` in **Migration 17** (`20261001000000`), which comes **after** Migration 12, 13, and 14 in timestamp order!
   - Consequently, when PostgreSQL executes migrations in canonical timestamp order, Migration 12 executes before Migration 17 exists, and fails with `SQLSTATE 42883 (Undefined Function)`.
