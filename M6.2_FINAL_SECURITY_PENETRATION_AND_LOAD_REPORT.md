## 3. Authentication Security

- **Session Architecture:** Supabase Auth JWT integration with PKCE flow for web and secure token persistence for mobile.
- **Brute-Force Protection:** Tier 1 rate limiting (10 requests/min) on authentication and privileged routes.
- **Session Lifecycle:** Evaluated expired session rejection (401 Unauthorized), logout token clearing, and suspended user session revocation.
- **Credential Integrity:** Zero plaintext passwords or JWT secrets stored in source code.

## 4. Authorization / RBAC

- **Role Separation:** 6 administrative roles (`super_admin`, `admin`, `content_admin`, `scholar_reviewer`, `support_admin`, `billing_admin`) strictly enforced at backend service level.
- **Privilege Escalation Defenses:**
  - Administrative self-role modification prohibited (`updateUserRole` throws error if `actor.id === targetUserId`).
  - Administrative self-suspension/unsuspension prohibited (`setUserSuspension` throws error if `actor.id === targetUserId`).
  - Super Admin account cannot be suspended or demoted.
  - Suspended administrators blocked from performing privileged actions.
- **Header Spoofing Defenses:** `x-admin-role` headers without verified matching `ADMIN_API_SECRET` are strictly rejected in production.

## 5. IDOR / Tenant Isolation

- **Bookmark Isolation:** User A cannot view, update, or delete User B's bookmarks (`auth.uid() = user_id`).
- **Reading Progress & Library:** User reading progress and personal notes strictly scoped to the authenticated user ID.
- **Deterministic Ownership:** Foreign key constraints with immutable user ownership triggers prevent cross-user ID substitution or parameter tampering.

## 6. RLS

- **Policy Verification:** 17 sequential SQL migrations inspectable with Row Level Security active on all private user tables (`bookmarks`, `profiles`, `user_prayer_settings`, `reading_progress`, `sync_queue`).
- **Administrative Access:** Enforced via `public.is_platform_admin(UUID DEFAULT auth.uid())` database function.
- **Theological Text Immutability:** Canonical scripture tables (`quran_surahs`, `quran_ayahs`, `hadith_narrations`, `duas`) have zero INSERT, UPDATE, or DELETE permissions granted to `anon` or `authenticated` roles.
- **Runtime RLS Status:** Evaluated statically and verified through database service mocks; live staging PostgreSQL execution remains an external infrastructure prerequisite.

## 7. Injection

- **SQL Injection:** Scanned 542 source/schema files; zero raw SQL string interpolations or unparameterized queries found (`scripts/security-audit-scanner.mjs`). All queries utilize PostgREST query builders or parameterized prepared statements.
- **Formula Injection:** CMS CSV/tabular exports sanitize formula prefix characters (`=`, `+`, `-`, `@`).

## 8. XSS

- **JSX Auto-Escaping:** Next.js React 18/19 DOM rendering automatically escapes text in Quran, Hadith, Dua, and Tafsir readers.
- **DangerouslySetInnerHTML Audit:** Exactly 1 application occurrence across the repository (`apps/web/src/lib/seo/json-ld.tsx`), strictly confined to JSON-LD metadata generation with full unicode entity escaping (`<` -> `\u003c`, `>` -> `\u003e`, `&` -> `\u0026`) to prevent script breakout.
- **Search Highlighting:** Search snippets sanitize highlighted matches without raw HTML injection.

## 12. Rate Limiting

- **Architecture:** Sliding-window in-memory rate limiter (`apps/web/src/lib/rate-limit.ts`) tracking client IPs via `CF-Connecting-IP`, `X-Real-IP`, and `X-Forwarded-For`.
- **Tier Configuration:**
  - Tier 1 (Auth/Privileged): 10 requests / 60 seconds
  - Tier 2 (Mutation/Search): 60 requests / 60 seconds
  - Tier 3 (Public Reads): 300 requests / 60 seconds
- **Local Stress Result:** 5,000 rapid requests processed with 3,000 allowed and 2,000 deterministically rejected (HTTP 429 simulation).
- **Architecture Note:** Single-process memory limiter is verified locally. Distributed multi-instance production deployment requires distributed/edge rate limiting (e.g., Cloudflare Rate Limiting or Redis).
