## 3. Internal Security Status

The internal application security posture was rigorously audited across all 542 source/schema files in the monorepo:
1. **Authentication & Session Security:** Supabase Auth JWT verification with PKCE flow active. Tier 1 rate limiting (10 req/min) protects authentication endpoints.
2. **Authorization & RBAC:** 6 distinct roles (`super_admin`, `admin`, `content_admin`, `scholar_reviewer`, `support_admin`, `billing_admin`) enforced at server boundaries. Self-role modification, self-suspension, and root Super Admin demotion are blocked at the service layer.
3. **Admin Header Spoofing:** Direct `x-admin-role` headers without verified matching `ADMIN_API_SECRET` are strictly rejected in production.
4. **Tenant Isolation & IDOR/BOLA:** Bookmarks, reading progress, and personal library items enforce `auth.uid() = user_id`. Cross-user data mutation and object tampering are blocked.
5. **Row Level Security (RLS):** 17 sequential migrations inspectable with active RLS on all personal data tables. Scripture tables are strictly read-only for `anon` and `authenticated` roles.
6. **Injection Protection:** 0 raw dynamic SQL string concatenations. 100% of queries parameterized via Supabase PostgREST client or PostgreSQL prepared statements.
7. **Cross-Site Scripting (XSS):** React JSX auto-escaping active on all reader views. The only application occurrence of `dangerouslySetInnerHTML` is in `apps/web/src/lib/seo/json-ld.tsx`, which enforces strict unicode character escaping (`<` -> `\u003c`, `>` -> `\u003e`, `&` -> `\u0026`) to prevent script breakout.
8. **SSRF & Open Redirects:** Zero arbitrary external URL fetch mechanisms exist in backend API routes. Zero unvalidated open redirect query parameters accepted.
9. **HTTP Security Headers:** Comprehensive defense-in-depth headers configured in `next.config.mjs` (HSTS with preload, CSP, X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin, Permissions-Policy).
10. **Mobile Client Security:** Encrypted Drift SQLite storage at rest via `sqlite3mc` (AES-256). GPS coordinates kept strictly in-memory during prayer calculations and never written to disk or synchronized.
11. **Secret Scanning:** 0 hardcoded production secrets, API keys, or private keys detected in the repository.
